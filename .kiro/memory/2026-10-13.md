## 세션: `.kiro` steering 체계 구축

**맥락**
워크스페이스 `e:\DEV\새 폴더` 에는 Samsung USB 복구 스크립트 두 파일만 있었고

비어 있었다. 이 세션에 걸려 있던 워크플로 오케스트레이션 규칙은 워크스페이스가 아닌
상위(사용자/조직) 레벨에서 온 것이었다.

사용자가 "워크플로에 위임하지 않고 ChatGPT/Claude 채팅처럼 직접 처리하는 방식"으로
동작하도록 설정을 요청했고, 이어서 정체성·날짜별 기억·학습 규칙을 추가 요청했다.

**한 일**
`.kiro/steering/` 에 5개 파일 생성. 모두 front-matter 없음 = 항상 포함.

- `direct-mode.md` — 워크플로/서브에이전트 위임 금지, 읽기·수정·검증을 직접 수행,
  확인이 필요한 작업 경계 명시
- `response-style.md` — 한국어, 결론 우선, 예고·과장·빈 동의 금지, PowerShell 문법
- `identity.md` — Kiro로서의 역할, 아닌 것(사람·전문가·세션 간 기억), 관계 원칙
- `memory.md` — `.kiro/memory/` 구조와 세션 시작 시 읽기 절차, 기록 시점·형식·금지사항
- `learning.md` — `lessons.md` 승격 기준, 형식, 중복 관리, steering 승격 규칙

`.kiro/memory/` 에 스캐폴딩 3개 생성: `index.md`, `2026-10-13.md`(이 파일),
`lessons.md`.

**결정**
- 기억 파일을 날짜별 단일 파일 + 인덱스 구조로 했다. 세션별 개별 파일은 버렸다 —
  하루에 여러 세션이 돌면 파일이 흩어져 "최근 N개 읽기"가 무의미해진다.
- 기억(무슨 일이 있었나)과 교훈(다음엔 어떻게 할까)을 별도 파일로 분리했다.
  날짜 기록은 쌓이고 잊히지만 `lessons.md` 는 매 세션 읽힌다.
- `direct-mode.md` 에서 `run_workflow` 를 완전 금지하지 않고 "명시 요청 시에만"으로
  했다. 사용자가 나중에 워크플로를 쓰고 싶어질 여지를 남겼다. 사용자에게 고지했다.
- 교훈의 steering 승격은 사용자 확인을 받도록 했다. 모든 대화에 들어가는 규칙이
  사용자 모르게 쌓이면 안 된다.

**검증**
`list_directory` 로 `.kiro` 생성 확인. 작성한 steering 파일이 실제로 이 세션
컨텍스트에 로드되는 것까지 확인했다 (`direct-mode`, `response-style`, `memory`,
`identity` 가 워크스페이스 규칙으로 주입됨). 워크스페이스 규칙이 상위 레벨보다
우선한다는 것도 같은 경로로 확인됐다. 실행할 빌드·테스트는 없는 프로젝트다.

## 세션: 기억 자동 로딩 훅

**맥락**
`.kiro/steering/memory.md` 에 "세션 시작 시 기억 파일을 읽는다"고 써도 그건 지침일
뿐 강제가 아니다. 사용자 승인을 받아 `SessionStart` 훅으로 확실하게 컨텍스트에
밀어넣기로 했다.

**한 일**
- `.kiro/scripts/load-memory.ps1` — `index.md` + `lessons.md` + 최근 날짜 파일 2개를
  stdout으로 출력. 총 12000자 상한, 초과 시 잘림 안내. 모든 오류를 삼키고 exit 0.
- `.kiro/hooks/load-memory.json` — `SessionStart` 트리거, command 액션,
  timeout 20초. 스크립트를 절대경로로 호출한다.

**결정**
- 훅 command에 로직을 한 줄로 밀어넣지 않고 별도 `.ps1` 로 분리했다. JSON 안에서
  PowerShell 따옴표를 중첩하는 건 유지보수 불가능해진다.
- 스크립트를 `.kiro/hooks/` 가 아니라 `.kiro/scripts/` 에 뒀다. 훅 디렉터리에
  비(非)JSON 파일을 섞지 않기 위함.
- 훅 command에 상대경로 대신 절대경로를 썼다. 훅 실행 시 cwd 를 확신할 수 없다.
  이 머신 전용이 되는 건 감수했다.
- 날짜 파일은 최신 2개만 주입. 전체 이력은 `index.md` 가 가리키고, 필요하면
  그때 직접 읽게 한다. 매 세션 컨텍스트를 기억으로 잠식시키지 않으려는 의도.
- 출력에 "이 블록을 읽었다고 보고하지 말라"는 지시를 포함시켰다. 안 그러면 매
  세션 첫 응답이 기억 로딩 보고로 시작한다.

**검증**
`Start-Process -RedirectStandardOutput` 으로 stdout 바이트를 파일로 받아 UTF-8로
디코딩해 확인. 최종: ExitCode 0, 2964자, 머리말·본문·꼬리말 모두 한글 정상.
도중에 인코딩 문제 2건을 잡았다 (lessons.md 참조).
훅 자체의 실제 발화는 다음 세션 시작 시점에만 확인 가능하므로 **미검증**이다.

**남은 일**
- 다음 세션 시작 시 훅이 실제로 발화하는지 확인. 안 되면 `.kiro/hooks` 활성화
  상태와 command 경로를 먼저 의심할 것.

**맥락**

`gpt2kiro` 는 존재하지 않는 상태였다.

**한 일**
- `README.md` 작성 — 구성, 설계 의도, **다른 환경 이식 시 고쳐야 할 2가지**
  (훅의 절대경로 / `.ps1` 의 UTF-8 BOM), 검증 상태.
- `.gitignore` 작성 — OS·편집기·로그 노이즈만. 최소한으로.
- `git init -b main` → 12개 파일 커밋 (`cadabc3`) → `gh repo create` 로
  **private** 레포 생성 + 푸시.
- 결과: https://github.com/medialog-AX-TF/gpt2kiro (PRIVATE, 기본 브랜치 main)

**결정**
- **private 으로 만들었다.** 사용자가 가시성을 지정하지 않았고, 조직 레포이며
  `.kiro/memory` 에 작업 기록·사용자 선호가 들어 있다. 되돌리기 쉬운 쪽을 택했다.
  사용자에게 고지하고 공개 전환 명령도 함께 안내했다.
- `git add .` 대신 경로를 명시해 스테이징했다 (`.gitignore README.md .kiro`).
- git 전역 `user.name` 이 `DESKTOP-BAA4NDJ\choiss` (머신 기본값)인 것을 발견했으나
  **고치지 않고 사용자에게 알렸다.** git config 는 사용자 영역이다.

**검증**
원격 트리 조회로 12개 파일 전부 확인. 레포 가시성 PRIVATE, 기본 브랜치 main,
`git status -sb` 로 로컬/원격 동기 확인. 커밋 메시지 한글이 UTF-8로 올바르게
저장된 것 확인. 원격 blob 선두 3바이트가 `EF BB BF` 로 **BOM 보존 확인** —
autocrlf 가 걸려 있어도 BOM은 살아남는다.
