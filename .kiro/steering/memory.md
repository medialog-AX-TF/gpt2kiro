# 날짜별 기억 파일

이 파일은 front-matter가 없으므로 모든 대화에 항상 포함된다.

세션 간 기억은 존재하지 않는다. 파일로 남긴 것만 다음 세션의 내가 알 수 있다.
그래서 기록은 선택이 아니라 작업의 일부다.

## 위치와 구조

```
.kiro/memory/
  ├─ index.md          전체 항목 목차 (최신이 위)
  ├─ lessons.md        누적 교훈 (learning.md 규칙 참조)
  └─ YYYY-MM-DD.md     해당 날짜의 작업 기록
```

날짜는 로컬 날짜 기준. 하루에 여러 세션이 있으면 같은 파일에 `## 세션` 블록을
추가한다. 새 파일을 만들지 않는다.

## 세션 시작 시

1. `.kiro/memory/index.md` 를 읽는다.
2. 가장 최근 날짜 파일 1~3개를 읽는다. 사용자의 요청이 특정 과거 작업과 연관되면
   index에서 해당 날짜를 찾아 그 파일도 읽는다.
3. `.kiro/memory/lessons.md` 를 읽는다.
4. 파일이나 디렉터리가 없으면 그냥 넘어간다. 없다고 보고하지 않는다.

이 읽기 과정을 사용자에게 중계하지 않는다. 조용히 읽고 바로 본론으로 들어간다.

## 기록 시점

- 작업을 끝냈을 때 (기능 구현, 버그 수정, 설정 변경)
- 설계 결정을 내렸을 때 — 특히 **왜 다른 대안을 버렸는지**
- 막혔거나 실패했을 때 — 무엇을 시도했고 왜 안 됐는지
- 사용자의 선호·제약을 알게 됐을 때 (쓰는 도구, 싫어하는 패턴, 환경 특이사항)
- 작업이 미완으로 끝날 때 — 남은 일과 재개 지점

사소한 질의응답 한 번으로는 기록하지 않는다. 다음 세션의 나에게 쓸모가 있는가,
이 한 가지로 판단한다.

## 기록 형식

```markdown
# 2026-10-13 (화)

## 세션: <주제 한 줄>

**맥락** 왜 이 작업을 하게 됐는지
**한 일** 변경한 파일과 내용. 경로는 워크스페이스 기준 상대경로
**결정** 선택한 것과 버린 대안, 그 이유
**검증** 실행한 명령과 결과. 검증하지 못했으면 그렇게 적는다
**남은 일** 없으면 "없음"
```

기록 후 `index.md` 에 한 줄 추가한다: `- [2026-10-13](2026-10-13.md) — 주제 요약`

## 기록하지 않는 것

- 비밀값: 토큰, API 키, 비밀번호, 인증서, `.env` 내용. 필요하면 **키 이름만** 적는다.
- 개인정보: 실명, 연락처, 주소, 계정 식별자.
- 코드 전문. 파일 경로와 함수명으로 가리킨다. 핵심 스니펫은 10줄 이내로.
- 확인하지 않은 추측을 사실처럼. 추측이면 "추측"이라고 표시한다.
- 터미널 출력 원문 덤프. 결론만 요약한다.

## 신뢰성

기억 파일은 과거의 내가 쓴 메모일 뿐이고 코드보다 먼저 낡는다.
기록과 현재 코드가 어긋나면 **코드가 맞다**. 어긋난 것을 발견하면 해당 항목을
수정하고 무엇이 바뀌었는지 덧붙인다.
