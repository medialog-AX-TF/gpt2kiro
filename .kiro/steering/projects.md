# 프로젝트

이 파일은 front-matter가 없으므로 모든 대화에 항상 포함된다.

주제별 작업 공간이다. 한 주제의 정의·제약·채팅 이력을 한 디렉터리에 모아두고,
그 프로젝트가 활성인 동안 매 세션 시작 시 컨텍스트로 주입한다.

`memory.md` 의 날짜 파일이 **시간 축**이라면 프로젝트는 **주제 축**이다.
날짜 축만으로는 "그 주제에 대해 지금까지 뭘 했나"를 모아 읽을 수가 없다.

## 구조

```
.kiro/projects/
  ├─ ACTIVE                        활성 프로젝트 slug 한 줄. 비어 있으면 활성 없음
  ├─ index.md                      전체 프로젝트 목록
  └─ <slug>/
     ├─ project.md                 정의: 목표·범위·제약·용어·참조. 매 세션 주입된다
     ├─ index.md                   이 프로젝트의 채팅 목차 (최신이 위)
     └─ chats/
        └─ YYYY-MM-DD-<주제>.md    세션 기록
```

`project.md` 는 ChatGPT Projects 의 custom instructions 에 해당한다. 매 세션
주입되므로 짧게 유지한다. 길어지면 참조 파일로 분리하고 경로만 적는다.

## 기록 위치 — memory.md 와의 관계

**활성 프로젝트가 있으면 세션 기록은 프로젝트의 `chats/` 에만 쓴다.**
`memory/YYYY-MM-DD.md` 에 같은 내용을 중복으로 쓰지 않는다. 두 곳에 쓰면
반드시 어긋나고, 어긋난 기록은 없는 기록보다 나쁘다.

대신 `memory/index.md` 에 한 줄 포인터만 남긴다:

```
- [2026-10-13](../projects/<slug>/chats/2026-10-13-주제.md) — [<slug>] 주제 요약
```

활성 프로젝트가 없을 때는 `memory.md` 규칙 그대로 날짜 파일에 쓴다.

`lessons.md` 는 **항상 전역**이다. 프로젝트 안으로 넣지 않는다. 교훈은 주제를
넘어 적용되고, 프로젝트별로 쪼개면 세 번째 프로젝트에서 같은 실수를 반복한다.

## 세션 시작 시

`load-project.ps1` 훅이 활성 프로젝트의 `project.md`, `index.md`, 최근 채팅
2개를 주입한다. 훅 출력이 있으면 그것으로 충분하다. 추가로 읽을 때는:

- 사용자의 요청이 주입된 최근 채팅보다 과거의 작업과 연관될 때 → 프로젝트
  `index.md` 에서 해당 항목을 찾아 그 채팅 파일을 읽는다.
- 활성 프로젝트가 없다고 주입됐고 사용자의 요청이 목록의 어느 프로젝트와
  명백히 관련될 때 → 그 프로젝트를 활성화할지 **묻는다**. 조용히 바꾸지 않는다.

읽기 과정을 중계하지 않는다.

## 프로젝트 생성

사용자가 새 주제의 작업을 시작하거나 명시적으로 요청할 때 만든다.

```powershell
.\.kiro\scripts\new-project.ps1 -Name "표시 이름" -Goal "한 줄 목표"
```

`-Slug` 를 주지 않으면 `-Name` 에서 파생한다. 생성 후 그 프로젝트가 활성이 된다.
`project.md` 의 범위·제약·용어는 템플릿 상태로 남으므로, 대화에서 알게 된 내용을
내가 채워 넣는다. 비워둔 템플릿은 주입 컨텍스트만 잡아먹는다.

세션 한두 번으로 끝날 일에는 만들지 않는다. 판단 기준은 **이 주제로 다시
돌아올 것인가**다. 아니면 날짜 파일에 쓴다.

## 프로젝트 전환

```powershell
.\.kiro\scripts\use-project.ps1 -Slug <slug>    # 전환
.\.kiro\scripts\use-project.ps1 -List           # 목록
.\.kiro\scripts\use-project.ps1 -Clear          # 활성 해제
```

`ACTIVE` 는 워크스페이스 전역이다. 세션별이 아니다. 여러 세션을 동시에 열어두고
전환하면 다른 세션의 **다음** 시작에 영향이 간다. 전환은 사용자가 요청할 때만
한다.

이번 세션만 다른 프로젝트를 보려면 `ACTIVE` 를 건드리지 말고 해당
`project.md` 와 채팅 파일을 직접 읽는다.

## 채팅 기록 형식

파일명은 `YYYY-MM-DD-<주제>.md`. 같은 날 같은 주제면 같은 파일에 `## 세션`
블록을 추가한다. 같은 날 다른 주제면 새 파일.

```markdown
# 2026-10-13 (화) — <주제>

프로젝트: <slug>

## 세션 1

**요청** 사용자가 원한 것. 사용자의 표현을 살려서 적는다
**진행** 주요 교환. 사용자가 방향을 바꾼 지점과 그 이유는 반드시 남긴다
**한 일** 변경한 파일과 내용. 워크스페이스 기준 상대경로
**결정** 선택한 것, 버린 대안, 이유
**검증** 실행한 명령과 결과. 검증하지 못했으면 그렇게 적는다
**남은 일** 없으면 "없음"
```

`요청` 과 `진행` 이 채팅 이력의 성격을 담는다. 결과만 남기면 다음 세션의 내가
"왜 이렇게 됐는지"를 복원할 수 없다.

기록 후 두 곳을 갱신한다.

1. 프로젝트 `index.md` 에 한 줄: `- [2026-10-13](chats/2026-10-13-주제.md) — 요약`
2. `memory/index.md` 에 포인터 한 줄 (위 "기록 위치" 참조)

기록하지 않는 것은 `memory.md` 와 동일하다 — 비밀값, 개인정보, 코드 전문,
터미널 출력 덤프, 확인하지 않은 추측.
