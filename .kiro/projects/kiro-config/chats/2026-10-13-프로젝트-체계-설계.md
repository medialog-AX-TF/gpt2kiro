# 2026-10-13 (화) — 프로젝트 체계 설계

프로젝트: kiro-config

## 세션 1

**요청**
"GPT 처럼 프로젝트를 생성하여 해당 주제에 관련한 채팅 이력을 남길수 있도록
설계해줘." 앞서 컨텍스트 상태와 내 역할·능력을 묻는 질문이 두 번 있었고,
그 흐름에서 나온 요청이다.

**진행**
기존 `.kiro/memory` 체계는 날짜 축(`YYYY-MM-DD.md`) 하나뿐이어서 "그 주제에
대해 지금까지 뭘 했나"를 모아 읽을 수 없다는 점을 문제로 잡았다. ChatGPT
Projects 의 구조(프로젝트 정의 + 그 안의 채팅 목록)를 주제 축으로 대응시켰다.

**한 일**
- `.kiro/steering/projects.md` — 프로젝트 운용 규칙. 항상 주입된다.
- `.kiro/scripts/load-project.ps1` — SessionStart 주입 스크립트
- `.kiro/scripts/new-project.ps1` — 스캐폴딩
- `.kiro/scripts/use-project.ps1` — 전환 / 목록 / 해제
- `.kiro/hooks/load-project.json` — SessionStart 훅 (절대경로)
- `.kiro/projects/` — `ACTIVE`, `index.md`, 첫 프로젝트 `kiro-config/`

**결정**

*단일 기록, 이중 색인.* 활성 프로젝트가 있으면 세션 기록은 그 프로젝트의
`chats/` 에만 쓰고, `memory/index.md` 에는 포인터 한 줄만 남긴다.
버린 대안은 양쪽에 전문을 쓰는 것 — 반드시 어긋나고, 어긋난 기록은 없는
기록보다 나쁘다.

*`lessons.md` 는 프로젝트 밖에 전역으로 유지.* 프로젝트별로 쪼개면 세 번째
프로젝트에서 같은 실수를 반복한다.

*`ACTIVE` 는 워크스페이스 전역 파일.* 세션별 스코프가 아니다. 세션별로 하려면
세션 식별자가 필요한데 훅 stdin JSON에 그것이 있는지 확인하지 않았다. 지금은
전역으로 두고, 한 세션만 다른 프로젝트를 볼 때는 `ACTIVE` 를 건드리지 않고
해당 디렉터리를 직접 읽기로 했다.

*자동 전환 없음.* 활성 프로젝트가 없을 때 스크립트는 프로젝트 "목록"만
주입하고, 전환 여부는 사용자에게 묻게 했다. 요청 내용으로 추측해 전환하면
엉뚱한 프로젝트에 기록이 쌓인다.

*slug 에 한글 허용.* 영문 slug 를 강제하면 매번 작명 비용이 든다. 파일시스템
금지 문자와 공백만 치환한다. `"테스트 프로젝트 (임시)"` →
`테스트-프로젝트-임시` 로 동작 확인.

*전사(transcript) 자동 수집은 하지 않음.* `Stop` 훅 stdin JSON에 대화 원문이
들어 있는지 확인하지 못했다. 확인되지 않은 것에 기능을 걸지 않고, 내가 직접
쓰는 요약 기록으로 간다. `요청`·`진행` 항목이 채팅 성격을 담당한다.

**검증**
- 세 `.ps1` 모두 선두 3바이트 `EF BB BF` 확인.
- `new-project.ps1` 2회 실행 — 첫 실행(`index.md` 생성 경로)과 두 번째
  실행(마커 아래 삽입 경로) 모두 정상. 한글 slug 파생과 `-NoActivate` 확인.
- `load-project.ps1` stdout을 파일로 받아 UTF-8 디코딩 — 791자, 한글 정상,
  exit 0. 활성 프로젝트가 있을 때와 없을 때 두 분기 모두 확인.
- `use-project.ps1` `-List` / `-Clear` / `-Slug` 모두 확인.
- 테스트 프로젝트는 삭제하고 `index.md` 항목도 제거했다. `ACTIVE` 는
  `kiro-config` 로 복원.
- **미검증**: 훅의 실제 발화. `SessionStart` 가 두 개(`load-memory`,
  `load-project`)가 됐을 때 둘 다 주입되는지는 다음 세션 시작 때만 확인된다.
  → **세션 2에서 확인 완료.** 둘 다 발화했다.

**남은 일**
다음 세션 시작 시 두 훅이 모두 발화하는지 확인. 하나만 뜨거나 순서 문제가
있으면 두 스크립트를 하나로 합치는 쪽을 검토한다. → 해소됨 (세션 2).

## 세션 2

**요청**
세션 1의 미검증 항목 — `SessionStart` 훅 두 개가 모두 발화하는지 확인.

**검증**
이 세션 시작 시 두 훅의 출력이 각각 **독립된 블록**으로 주입됐다.
`load-memory.ps1` 의 `=== 이전 세션 기억 (.kiro/memory) ===` 와
`load-project.ps1` 의 `=== 활성 프로젝트: kiro-config ===` 모두 정상, 한글도
깨지지 않았다. 같은 트리거에 훅 JSON 파일이 여러 개여도 모두 실행된다.

**결정**
두 스크립트를 합치지 않는다. 날짜 축(memory)과 주제 축(projects)은 관심사가
다르고, 각각 독립적으로 켜고 끌 수 있는 쪽이 낫다.
